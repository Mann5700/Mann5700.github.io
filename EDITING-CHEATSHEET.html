Running and changing your site

Everything a visitor reads lives in Markdown files you can edit straight on GitHub.com. The heavier jobs — a new resume, a new backdrop image — need a laptop. This sheet covers both, plus how to tell a deploy worked and how to undo one.

The short answer

Yes — text changes are point-and-click. Edit a file on github.com, click Commit changes, and the site rebuilds and republishes itself. Live at mann5700.github.io in about a minute. Nothing to install, nothing to run.

Needs a laptop: replacing the resume PDF (section 9), swapping the nebula backdrop (section 10), and upgrading dependencies (section 12). Everything else here is a browser edit.

01The deploy loop

  1. YOUEdit & commitChange text in a .md file on github.com.
  2. AUTOChecks runContent validated, types checked.
  3. AUTORebuildPages regenerated from your text.
  4. AUTOLivePublished to mann5700.github.io, ~1 min.

The important guarantee: a broken edit cannot take your site down. The checks run before anything is published, so a bad file just stops the deploy — the live site keeps serving the previous version. You get a red ✗ in the Actions tab naming the file and the field.

03The click-by-click routine

  1. Go to github.com/Mann5700/Mann5700.github.io.
  2. Click into the folders — e.g. src → content → projects → reqbridge.md.
  3. Click the pencil icon at the top right of the file.
  4. Change only the words. Leave field names, colons, dashes and indentation exactly as they are.
  5. Commit changes… → short message → keep Commit directly to the main branch → confirm.
  6. Actions tab → wait for the green ✓ (about a minute).
  7. Open the site and hard-refresh: Ctrl+Shift+R.
Doing it from the laptop instead

In Documents\Mann Portfolio Website:

npm run dev        # live preview at localhost:4321 while you type
npm run verify     # validate + type-check + build, before you push
git add -A
git commit -m "Update mission copy"
git push

If push complains about certificates on a corporate network, use git -c http.sslBackend=schannel push.

04How a content file is built

Two parts. Between the two --- lines are structured fields the site reads. Below the second --- is free prose — write whatever you want there, in normal Markdown. 

--- <- fields start
title: ReqBridge
tagline: Requirements Intelligence Engine
order: 1
technologies:
  - Python
  - LangGraph
--- <- fields end

Normal sentences down here. **Bold** and *italic* work.
Leave a blank line between paragraphs.

Five rules that prevent every common breakage

  1. Never rename the word before a colon. title:, order:, summary: are wiring, not labels.
  2. Spaces, never Tab. Copy the line above and edit it rather than typing indentation from scratch.
  3. List items are dash + space + text. - Python, never -Python.
  4. Text containing a colon-space must be wrapped in double quotes, or moved into a >- block.
  5. Inside a >- block, keep every line indented by the same two spaces.

✓ Safe

tagline: Fewer meetings, more shipping
description: >-
  A long paragraph that can
  wrap over several lines as
  long as each stays indented
  by two spaces.
role: "Engineer: Platform"

✗ Breaks the build

Tagline: Fewer meetings
role: Engineer: Platform
technologies:
-Python
description: >-
Not indented, so YAML
loses the block.

05Recipes — the usual edits

Headline, bio, availability, the four metrics

All in src/content/profile/profile.md:

role: Software Engineer              # sits under your name
headline: I build AI-augmented…      # the big statement
location: Jersey City, NJ
availability: Open to interesting problems   # delete line to hide
metrics:                             # exactly 4 max
  - value: 4+ hrs
    label: PI Planning saved per dev team, per sprint

The paragraphs below the closing --- are your "about" text — rewrite freely.

Edit an existing mission

src/content/projects/<name>.md. Fields you'll actually touch: title, tagline, description (the card summary), problem, approach, architecture (bullets), decisions (title + detail pairs), outcomes (value + label pairs). Delete any optional field you don't want and it simply stops rendering.

Values that must be exact:

  • order — lower number appears first.
  • featured: true — promotes it to a full-width case study.
  • status — one of active, shipped, archived.
  • theme — one of ember, ion, dust, void.
  • year — 2026 or 2026-04.

Add a new mission

  1. Open src/content/projects/_template.md, copy all of it.
  2. In the projects folder: Add file → Create new file.
  3. Name it my-new-project.md — lowercase, hyphens, no spaces. The filename becomes the URL: /missions/my-new-project/.
  4. Paste, fill in, delete the commented-out lines you don't need, commit.

The card and the full detail page both build themselves. No other file to update.

Remove a mission

Open the file → ⋯ → Delete file → commit. Keep at least one; an empty folder fails the build.

Add or edit a job

src/content/experience/<name>.md. Dates are YYYY-MM. For your current job use current: true and omit end — it shows "Present". order: 1 is the newest role.

Skills

label: Languages
order: 1
items:
  - Java
  - name: Python
    note: Primary language day to day
    core: true          # renders brighter

One file per group in src/content/skills/. Delete a file to drop the whole group.

Certifications, awards, talks, papers

One file per item in src/content/credentials/. kind must be certification, award, publication or talk. The whole section appears only when at least one non-draft entry exists, and disappears again if you remove them all.

Social links

The socials: list in profile.md drives the nav, the Signal section, the footer and the search-engine data at once. One place, four effects.

06What not to touch

Leave these alone
  • src/layouts/, src/lib/, src/scripts/ — plumbing and animation logic.
  • src/content.config.ts — the rulebook your content is checked against.
  • astro.config.mjs, package.json, package-lock.json, tsconfig.json.
  • .github/workflows/deploy.yml — the thing that publishes the site.
  • Anything inside < > angle brackets, and any class="…" value.

If you rename a section

The name appears in two places: the component's title= and the SECTIONS list in src/lib/site.ts. Change both or the nav and the heading disagree. Do not change the id values in SECTIONS — those are the anchor links.

08Changing the look without touching components

src/styles/tokens.css holds every colour, type size, spacing step, radius and easing curve on the site. Changing one line re-tints everything consistently: 

--c-ember: #ff9d5c;   /* the warm accent — buttons, numbers, highlights */
--c-ion:   #9fd9ff;   /* the cool accent — links, secondary detail    */
--c-void:  #05060a;   /* page background                              */
One caution

The palette was tuned to pass WCAG AA contrast. If you lighten the background or darken the text, check that body copy still reads clearly — a pretty colour that fails contrast is a real accessibility regression, and it is the one "cosmetic" change that can actually make the site worse.

09Replacing the resume

Read this first

Never drop your personal resume PDF into public/. The copy you email people carries your phone number. Anything under public/ is downloaded, indexed and scraped — you cannot take it back.

On the laptop, in Documents\Mann Portfolio Website:

  1. Save the new full resume at the project root as Mann Patel Resume.pdf. The root *.pdf pattern is gitignored, so it never gets committed.
  2. Run npm run resume. It removes the phone number from the PDF's content stream (a real redaction, not a black box over it), strips authoring metadata, keeps the fonts and the email/GitHub/LinkedIn links, writes public/resume/Mann-Patel-Resume.pdf, and rasterises the preview images the on-page viewer shows. It exits with an error if a phone number survives, so it cannot fail quietly.
  3. Update resume.updated in src/content/profile/profile.md to the new month, e.g. 2026-11.
  4. If the filename changed, update resume.href too — npm run validate fails if it and the file on disk disagree.
  5. npm run verify, then commit and push.

One-off prerequisite: pip install pymupdf. Deploys never need Python — the redacted PDF is committed.

To check any PDF yourself:

python -c "import fitz; print(fitz.open('public/resume/Mann-Patel-Resume.pdf')[0].get_text()[:300])"

Changing only the date shown beside the resume, with no new PDF, is a plain browser edit of resume.updated.

10Backdrop image and social preview card

Swap the nebula

  1. Put the full-resolution image at assets-src/crab-nebula.jpg. That folder is gitignored, so the heavy original never enters the repo.
  2. Adjust CROP at the top of scripts/build-backdrop.mjs — the image is shown as a feathered shape, so the crop needs to frame the subject, not the centre of the plate.
  3. npm run backdrop — writes AVIF and WebP at eight widths (480 → 3864) into public/images/nebula/, which is committed.
  4. npm run og — rebuilds the social preview card from the same image.
  5. Update the credit line in src/components/Footer.astro.
  6. npm run verify, commit, push.

Just the link preview card

npm run og regenerates public/og/og.png (1200×630) — this is what shows up when the site is pasted into LinkedIn, Slack or iMessage. Re-run it after you change your name or title so the card doesn't contradict the page.

Preview caches

LinkedIn and Slack cache preview cards hard. After changing the OG image, expect the old card to persist for a while — that's their cache, not your site. LinkedIn's Post Inspector can force a refresh.

Favicon and app icons

public/favicon.svg and public/icons/ (icon-192.png, icon-512.png, apple-touch-icon.png). Replace the files with same-sized versions using the same names and nothing else changes.

11Did it publish? And how to undo it

Check the deploy

  1. Actions tab → newest run on top.
  2. Green ✓ = live. Yellow dot = building, wait. Red ✗ = not published, site unchanged.
  3. On red, click the run → the failed step → the last red lines name the file and the field. Fix and commit again.
Message you'll seeWhat it means
Missing required field "order"You deleted a line the schema needs. Put it back.
Field "…" must be textUsually an unquoted value containing a colon.
Invalid enum valuestatus or theme is a word that isn't on the allowed list.
points resume.href at … does not existThe PDF path and the actual file disagree.
Anything mentioning YAMLIndentation or a stray dash. Compare against a file you didn't touch.

Still seeing the old version?

Browser cache, not the site. Hard-refresh: Ctrl+Shift+R (⌘+Shift+R on Mac), or open a private window.

Undo

  1. Commits → click the commit you regret → Revert.
  2. Confirm. The previous version redeploys on its own in about a minute.

Nothing is ever lost — every version of every sentence is in the history.

Renaming a project repo

If you rename a repo on GitHub, the links.github URL inside the matching src/content/projects/*.md still works (GitHub redirects), but it's worth updating so the link is honest. Nothing breaks either way.

13If something looks properly broken

SymptomCause & fix
Site is the old version despite a green ✓Browser cache. Hard-refresh, or private window.
A section vanishedIts folder is empty, or every entry is a draft. Add an entry back.
A project page 404sThe filename changed, so the URL changed. Filenames are the URLs.
Everything looks unstyledAlmost always a half-saved edit in a component file. Revert that commit.
npm install fails on certificatesCorporate network. The repo ships a local .npmrc workaround — see the README's Troubleshooting section.
Local dev shows stale stylesStop the server, delete node_modules\.vite, start again.

Worst case, you can always get back to a known-good site: find the last commit with a green ✓ in the Actions tab and revert everything after it. The site is static files — there is no database to corrupt and no server to fall over.

14One-minute summary

  • Words live in src/content/. Edit on github.com, commit to main, done.
  • Publishing is automatic, about a minute, nothing to run.
  • Change words — never field names, indentation or punctuation structure.
  • A bad edit can't break the live site; it just refuses to publish.
  • New mission = new .md copied from _template.md. Filename = URL.
  • Resume, backdrop and OG card are the only laptop jobs: npm run resume / backdrop / og.
  • Always npm run verify before pushing from the laptop.
  • Hard-refresh before believing it didn't update.
